## 2. 阅读与实现边界

先读取 `docs/README.md`、本文件，以及技术架构的 `5.1`、`6.0~6.2`、`7.1`、`9`、`17`、`18.1`、`19.1`、`20.1`、`20.4`。按步骤读取：

- `cmd/loginserver/`、`internal/app/loginserver/`、`internal/platform/account/`、`internal/platform/login/`。
- `internal/infra/db/`、`internal/repo/`、`internal/testutil/testdb/`。
- `internal/platform/auth/` 与相关 GameServer 接入代码，仅核对票据和玩家初始化边界。
- `configs/loginserver.*.yaml`、`scripts/loadtest/`、`README.md`、`docs/ops/runbook.md`。

固定边界：

1. LoginServer 与 GameServer 独立运行；客户端凭入场票直连目标 GameServer，复用现有分配器、签票器和首帧鉴权。
2. 内部 UID 由本服务生成，`players.uid` 保持稳定；外部标识只能作为身份映射键。玩家数据仍由 GameServer 原有流程初始化。
3. `platform/account` 负责身份验证、账号状态和登录态；`platform/login` 只接收已验证 UID 并分配、签票；Repository 只持久化；`app/loginserver` 负责配置、HTTP 和资源组装。
4. 自建身份映射到内部账号，同一身份只能属于一个 UID。增补支持游客持有效 session 绑定新的用户名密码并保留 UID；后续平台绑定须验证双方身份，拒绝跨 UID 转移。不实现外部平台、解绑、换绑和密码找回。
5. 撤销、封禁或删除阻止续期和签发新票。已签入场票按原 TTL 失效，存量 WS 不因本任务即时踢下线；GameServer 不访问账号认证表。
6. 删除未上线的 `account=uid` 信任路径，不保留旧协议兼容入口。不修改玩法、GameServer 业务协议、数据库分片或 Redis 拓扑，不实现支付、实名认证或角色转服。
7. 账号会话不以 Redis 为唯一权威状态；业务进程不得执行 DDL。账号初始化 SQL 已独立提供，入口见技术架构 9.12；其他模块完整 SQL 仍在首次上线前统一整理。
8. 开发阶段只按最终协议、Model 和建表 SQL 实现；不保留旧数据兼容、双读双写、运行时迁移分支或中间模型。废弃方案直接移除，测试与当前规则同步。

### AD-06 HTTP

Handler 只解析 DTO、调用 Service 和映射公开错误。账号认证独立于选服；进入与重连先验证会话和账号状态，再分配、签票。落实可信 IP、限流、请求体限制和错误脱敏；不把客户端 `client_ip` 或未受信任转发头作为限流依据，不直接返回内部错误字符串。

### AD-07 组装

LoginServer 创建独立账号数据库连接，凭证由环境变量提供。配置、依赖或监听失败时拒绝启动并释放资源；停止时先结束 HTTP 请求，再关闭 MySQL、Redis。GameServer 不增加账号数据库依赖。
